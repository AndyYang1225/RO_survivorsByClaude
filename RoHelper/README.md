# RO Survivors 小幫手（exe 版）

取代 Tampermonkey 腳本 v7.5。雙擊 `RoHelper.exe` 就會開遊戲並自動掛上小幫手，控制面板是獨立視窗。

## 目前狀態：只有視覺模式
- 只用視覺模式，不在遊戲網頁注入任何 JS。舊的 JS 引擎（注入、自動更新、模式切換）已從程式碼刪除（2026-11-24），要看舊版請找 git tag `js-engine-last`。
- 視覺模式已補齊舊版 JS 的功能（計畫 4、5，2026-11-21）：大廳流程（含首頁、選角色、捨棄未完成的一局）、自動活動與**自動遠征**、選卡（含尋寶率、累積升級按 B）、**野外走位**（小地圖撿掉落物／磁鐵／寶箱、扭蛋、繞圈、卡住繞路、王死掉的地點、MVP 撿取倒數、**躲到鐘下**）、戰績紀錄、職業與地名偵測。唯一還沒做的是「HP 低時去吃肉」（還沒看過肉的樣子）。
- 尋寶率是把滑鼠移到下方道具上讀說明框算出來的（只在選卡後、道具變動時讀，每次約 1 秒不走位）。
- 節慶扭蛋目前只找實機確認過的珊瑚粉紅色（其他顏色規則會把寶箱、閃電、水晶光暈當成扭蛋）。
- 「學到後放逐」和「一出現就放逐」的卡都放逐過後，會按遊戲的「自動」，這局之後交給遊戲選（面板「選卡 → 規則」可關）。遊戲 2026.11.23 版起「自動」分成升級卡的「自動技能」和寶箱卡的自動兩顆，小幫手分開記、各按一次；「寶箱卡也按遊戲的自動」關掉的話，寶箱卡繼續照規則（尋寶率、神祇、道具）由小幫手選。
- 技能神祇（遊戲 2026.11.23 版起）：角色約 20 等時道具欄會出現紫色「!」，小幫手在野外看到就點開，在「選擇你的神祇」照面板「神祇」頁的技能神祇順序選（打 ✕ 的不選），都沒有就照「技能」頁順序，再沒有選第一張。每局只選一次，之後神祇自己升級。跟「升級卡自動選」一起開關。
- 寶箱卡單張重抽：寶箱卡都不是要的（勾選的道具、優先的神器、尋寶率卡、這局拿過的道具）時，挑「同類有要的」那張按「重抽卡片」（單張重抽只會換成同一類），直到出現要的；單張用完改按重抽全部，都用完照規則選。組隊時每個畫面最多重抽 3 次。面板「選卡 → 規則」可關。
- 選卡判讀有問題時：在選卡畫面按 F8 暫停 →「視覺除錯」→「截一張」→「讀選卡」，記錄欄會列出每張卡讀到的內容。
- `runs.jsonl`（每局戰績）視覺模式也會寫。

## 使用
- **F8**：暫停／繼續（遊戲或面板有焦點時都可以按）
- **F9**：顯示／隱藏面板（面板按 X 也只是隱藏）
- 面板（2026-11-25 改版）：左側導覽「總覽／選卡／走位／出發／紀錄／其他」，選卡底下再分「規則／技能／神祇／道具」。改了設定右下角會出現「已儲存 ✓」。舊版面板可在遊戲視窗「選項 → 新版面板」關掉後重新啟動切回（第 3 階段會移除）。
- 遊戲視窗上方選單：面板、重新載入、開發者工具、開啟資料夾、多開總覽、選項（靜音、啟動時自動繼續、卡住時自動重新整理）
- 標題列顯示「[分身] 第 N 局｜目前動作」；卡住且救不回來時顯示 ⚠ 並讓工作列閃爍
- 從 Tampermonkey 版搬設定：舊面板「其他 → 匯出設定（複製）」→ 新面板「其他 → 匯入設定」貼上

## 多開（同時跑多個帳號）
- 每個帳號一個 profile：`RoHelper.exe --profile=A`、`RoHelper.exe --profile=B`（名稱只能用英數、- 和 _）。也可以從選單「多開總覽 → 新增分身…」開，會自動帶參數並可在桌面建立捷徑。
- 每個 profile 有自己的設定、戰績、截圖、視窗位置和**登入狀態**（`%AppData%\RoHelper\profiles\名稱\`、`%LocalAppData%\RoHelper\profiles\名稱\WebView2`）；範本共用。第一次開某個 profile 要登入一次，規則設定會從預設 profile 複製一份當起點。
- 同一個 profile 只能開一個；不帶 `--profile` 就是原本的那一份。視窗和面板標題會顯示 [名稱]。
- 同一個帳號不能同時登入兩個視窗。每多開一個就多一個 3D 畫面＋截圖判讀。
- 建議把遊戲內的畫面更新率設成 30 Hz（瀏覽器預設跟著螢幕更新率繪製）。實測（i5-12400F、RTX 3060、199 Hz 螢幕）：改成 30 Hz 後瀏覽器 CPU 少了約 43%，每個視窗約佔整台電腦 8% CPU，推估可以同時跑 5 個（實測過 3 個）。
- 開發介面多開時要給不同 port：`--profile=B --dev-api=8766`。從總覽開的分身，如果目前視窗有開發介面，會照名稱自動分配（A＝8765、B＝8766、C＝8767…）。
- 多開總覽讀各 profile 資料夾的 `status.json`（每個視窗至少每 15 秒寫一次；超過 60 秒沒更新算沒在執行）。
- 面板「其他 → 套用到其他分身…」：在對方資料夾放 `config.pending.json`，對方主迴圈收到後併進設定再刪掉（不能直接改對方的 config.json：對方執行中時下次存檔會蓋掉）。不送局數、戰績、職業偵測、活動／遠征選擇（expe 開頭）、局數上限和組隊角色。

## 組隊（遊戲 2026.11.23 版起，最多 3 人）
- 前提：隊長和隊員的帳號在遊戲裡互加好友（右上「好友」→ 輸入角色名 →「加入」，只要做一次）；每個帳號用一個分身（多開）。
- 面板「出發 → 大廳 → 組隊」：一個分身選「隊長」並開自動遠征（選地圖、難度照遠征設定）；其他選「隊員」（也要開自動遠征，才會處理首頁、選角色、結算）。「組隊的大廳」大家要選同一個。
- 全自動流程：
  1. 「選擇大廳」視窗用 OCR 找指定的多人大廳（單人大廳不能組隊）。
  2. 隊長在大廳看右下角隊伍面板，本機的隊員分身（同一個大廳、正在執行）還沒在隊上就打開好友名單「邀請組隊」；隊員到齊才去找遠征隊長（最多等約 2 分鐘，之後帶著到齊的人先出發）。三個帳號都下線隊伍就會解散，所以每次重開都會自動重新組。
  3. 隊員收到「X 邀請你加入隊伍」：**只接受本機隊長分身的邀請**（比對角色名），別人的邀請一律拒絕；接著「隊長在頻道 N」→「前往頻道」。
  4. 隊長：選地圖 → 出發 → 難度對話框按「向隊伍提議」；隊員看到「X 想與隊伍一同出發」按「準備好了！」。按完先等（最多 60 秒），看到野外的計時器才算開局、開始走位（等待中隊長不會再去找遠征隊長）。
- 組隊時原地站樁（預設開）：組隊時各自走位會越走越散、各自被包圍（2026-11-24 斐揚森林全拉滿實測：各自走位約 4 分鐘全滅，三人站著不動撐了約 15 分鐘）；開著時不繞圈、不追寶箱，躲鐘和 MVP 死後撿東西照常。
- 戰利品分配：結算畫面「隊伍戰利品」，不做任何操作時遊戲自動讓每個人 Greed 擲骰、點數高的拿走（實測沒有要玩家按的擲骰視窗）。
- 角色名：各分身進野外時從左上角角色框讀到後存在設定的 `charName`（隊長靠它知道要邀請誰、隊員靠它認隊長）；比對容許 OCR 讀錯幾個字。
- 邀請時每一步的畫面和 OCR 結果存在 `shots\party`（最多 100 張），出問題時看這裡。
- 安全：好友選單只按 OCR 確實讀到的「邀請組隊」（已組隊的人選單最後一項是「檢舉」，不能照位置按）；名單上標「組隊中」的人不邀請。
- 需要的範本：向隊伍提議、準備好了、前往頻道（2026-11-23 已存）。隊員局數到上限時不接受出發提議。

## 掛機
- 按遊戲視窗的「最小化」時，視窗其實是移到螢幕外，遊戲照常跑（真的最小化，WebView2 會讓遊戲暫停）。點工作列或 Alt+Tab 就會回來。
- 例外：Win+D（顯示桌面）是由系統直接最小化，這時遊戲還是會暫停。
- 不想要這個行為：把 `app.json` 的 `KeepRunningWhenMinimized` 改成 `false`。

## 開發
- 規則清單的來源是 `Engine/engine.js` 裡的 `RULES`（舊 JS 引擎留下的，程式本身不會執行它）；面板依產生出來的 `Engine/schema.json` 自動長出規則欄位。
- 建置：`dotnet build`；發佈單一 exe（自帶 .NET）：`dotnet publish -c Release -o publish`
- 測試：`dotnet test ..\RoHelper.Tests`（測試專案跟 RoHelper 資料夾平行，避免被主專案一起編譯）
- 建置輸出路徑：TFM 改成 `net8.0-windows10.0.19041.0`（OCR 需要 WinRT），所以輸出在 `bin\Debug\net8.0-windows10.0.19041.0\`

## 視覺判斷（開發中，不碰網頁）
完全不在遊戲頁面注入 JS，只看截圖判斷、用瀏覽器層級的真實輸入操作。
- F8／F9 由 exe 處理（WebView2 把功能鍵轉給 WinForms）
- 視覺模式需要的範本（名稱要一字不差）：單人大廳、開始遊戲、前往野外、返回角色、節慶主持人、交談提示。後兩個存範本時要勾「整張畫面找」；缺哪個面板會顯示「缺少範本」
- 規則清單：視覺模式用內建的 `Engine/schema.json`。改了 `engine.js` 的規則要重新產生：`node tools/gen-schema.js RoHelper/Engine/engine.js > RoHelper/Engine/schema.json`（在 `C:Ro` 執行；`BuiltInSchemaTests` 會檢查有沒有忘記）
- 遊戲視窗選單「視覺除錯」：即時截圖、點擊測試、框選 OCR、存範本、找範本
- 截圖用 Windows 的 PrintWindow（約 50 ms，視窗移到螢幕外掛機時也截得到）
- 範本內建在 exe（專案的 `Templates` 資料夾，要更新內建範本就把新的 png／json 放進去）；`%AppData%\RoHelper\templates` 裡同名的範本優先。每個範本是 `名稱.png`＋`名稱.json`（`X/Y/W/H`＝搜尋範圍佔截圖的比例、`Threshold`＝門檻、`Dpr`＝截圖當下的顯示縮放）
- OCR 需要 Windows 的繁體中文 OCR 語言套件（設定 → 時間與語言 → 語言與地區 → 中文（台灣）→ 光學字元辨識）
- 計畫書：`C:\Ro\docs\superpowers\plans\`

## 開發介面（給 Claude 用，預設關閉）
用 `dotnet run -c Release --project RoHelper -- --dev-api`（或 `RoHelper.exe --dev-api[=port]`）啟動時，在 `http://127.0.0.1:8765/` 開一個本機 HTTP 介面，讓 Claude 自己截圖、讀畫面、操作；同時自動存證據。沒帶這個參數時程式行為完全不變。

| 端點 | 用途 |
|---|---|
| `GET /` | 端點清單 |
| `GET /status?n=30` | 暫停、局數、目前動作、最近的狀態紀錄、本局選卡狀態 |
| `GET /shot?name=xxx` | 截一張存到 `shots\api\`，回路徑 |
| `GET /screen` | 每個大廳範本的最佳位置、分數、門檻 |
| `GET /picker` | 讀選卡畫面＋現在設定下會怎麼選（只預覽） |
| `GET /field` | 讀小地圖（自己、磁鐵、寶箱、掉落物、王）＋現在設定下會怎麼走（只預覽） |
| `POST /click?x=&y=`、`POST /move?x=&y=`、`POST /key?k=1` | 點擊、移動滑鼠（截圖像素座標）、按鍵（一個英文字母或數字） |
| `POST /type?text=` | 在目前的輸入框打字（使用者要 Claude 幫忙登入測試帳號時用） |
| `POST /pause`、`POST /resume` | 暫停、繼續 |
| `POST /templates/reload` | 重新讀範本 |
| `POST /templates/save?name=&shot=&x=&y=&w=&h=[&threshold=0.9]` | 從 `shots\` 底下的截圖裁一塊存成範本（同名範本沿用原搜尋範圍） |
| `GET /evidence?n=20` | 最近自動存的證據 |

- 範例：`curl -s 127.0.0.1:8765/status`、`curl -s -d "" "127.0.0.1:8765/click?x=950&y=640"`
- POST 要帶 `-d ""`：只寫 `-X POST` 時 curl 不送 Content-Length，Windows 的 HTTP.sys 會直接回 411，請求到不了程式。
- 中文參數要自己先編成 UTF-8 的 %XX（例如 `node -p "encodeURIComponent('返回角色')"`）：Git Bash 的 curl 用 `--data-urlencode` 時會把中文轉成 Big5 送出，存出來的檔名是亂碼。
- **自動存證據**：讀不到卡名、選卡按鍵沒反應、例外時（同一種 60 秒內只存一次），以及每 5 分鐘一張，存到 `%AppData%\RoHelper\shots\auto\`（PNG＋同名 JSON，最多 150 張，超過刪最舊的）。
- 安全：只聽 127.0.0.1（其他電腦連不到）、不加驗證。`/type` 可以打字，所以同一台電腦上的其他程式也能透過它操作遊戲；只在需要時才帶 `--dev-api` 啟動。

## 卡住偵測
- 實測時 A 視窗被網頁對話框擋住 8.5 小時沒人發現，所以加了 StallWatch：
  - 畫面 3 分鐘完全沒變（截圖指紋一樣），或主迴圈根本沒在跑 → 視為凍結
  - 45 分鐘沒有開新局也沒有結算（正常一局 15～22 分鐘）→ 視為流程卡住
- 處理：重新整理頁面（最多 2 次，交給大廳流程從首頁接手）；還是不行就標題列顯示 ⚠、工作列閃爍，之後不再動作。開新局或結算後歸零。
- 暫停、局數達上限、沒開自動活動／遠征時不算卡住。紀錄寫在 `events.log`。選單「選項 → 卡住時自動重新整理」可以關掉。
- CDP 輸入最多等 10 秒，逾時這一輪就結束，免得網頁沒回應時主迴圈卡死。

## 網頁對話框
- 網頁的 alert／confirm 由程式處理（WebView2 的 ScriptDialogOpening，不是注入 JS）：瀏覽器原生對話框會擋住整個網頁，模擬點擊點不到。
- alert 一律按確定，訊息記到 profile 資料夾的 `events.log`（卡住偵測的處理也記在這裡）；「帳號在另一台裝置上使用過」按掉後重新整理，由大廳流程從首頁接手。
- confirm／prompt 會跳視窗讓使用者決定。
