# 控制面板改版設計

日期：2026-11-25
狀態：設計已確認，待寫實作計畫

## 背景與目標

使用者回報面板體驗不佳，四個痛點都有：

1. 外觀老舊（WinForms 預設灰色控制項、排版擠）
2. 操作不順手（改了設定不確定有沒有生效等）
3. 看不出程式在做什麼（狀態只有上方一行「→ 動作」文字）
4. 設定太多太亂（約 54 項規則分在 7 個分頁）

使用習慣：程式在跑時**大多只看狀態**，設定很少動。所以改版的主軸是「一眼看懂現在的狀況」，設定整理好、但放在次要位置。

## 版面

### 頂端列（每一頁都有）

- 狀態燈：綠＝運行中、黃＝暫停
- 「運行中 · 第 N 局」（有局數上限時顯示「第 N / M 局」）
- 📌 面板置頂（切換）
- ⏸ 暫停 F8（切換）
- 多開時標題顯示 profile 名稱（同現在的視窗標題）

### 左側導覽與內容

| 導覽 | 內容 | 來源 |
|---|---|---|
| 📊 總覽 | 儀表板（見下一節） | 新增 |
| 🃏 選卡 | 上方小分頁：規則／技能／神祇／道具 | 原「升級」「技能」「神祇」「道具」 |
| 🚶 走位 | 走位規則，頁內分組（撿東西、躲避、移動方式） | 原「走位」 |
| 🗺 出發 | 遠征（地圖、難度、①～④）、活動、組隊、局數上限 | 原「出發」 |
| 📜 紀錄 | 戰績（最近 10 局）、完整對局紀錄、選卡紀錄開關（debugLog） | 原「其他」的紀錄區 |
| ⚙ 其他 | 速度與時間（所有 t 開頭的時間設定）、設定備份（匯入、匯出、套用到其他分身） | 原「其他」 |

導覽目前在哪一頁照舊存進設定的 `tab`，下次打開回到同一頁。

### 總覽頁

由上到下：

1. **異常警示**：有異常才出現，沒有時整區不佔空間。
   - 紅（程式會自己處理的嚴重狀況）：畫面沒變化、即將自動重新整理（StallWatch）；辨識失敗（「視覺判斷失敗」）。
   - 黃（需要使用者注意）：沒偵測到職業（技能規則不生效）、缺少範本、沒有繁中 OCR。
2. **現在在哪一步**：
   - 步驟條依模式切換。遠征：大廳 → 隊長 → 選地圖 → 出發 → 野外 → 結算；活動：大廳 → 主持人 → 開始 → 野外 → 結算。已完成的步驟淡藍、目前步驟深藍。
   - 下方大字是目前動作，再下面是最近 3 筆動作紀錄（時間＋動作）。
   - 暫停時步驟條變灰，動作顯示「已暫停」。
3. **本局**（在野外時）：地名與職業、遊戲時間、下一隻王倒數、尋寶率、HP 條、這局選過的卡（藍＝技能、橘＝寶箱）。
   **上一局**（不在野外時）：時長、結果（存活／死亡）、尋寶率。
4. **今天累計**：局數、每小時局數、存活率、開始時間，加上最近 10 局時長的長條圖（紅＝死亡）。

### 設定頁的呈現

- 每項設定一列：開關＋短標題；數字欄位在同一列右邊；長說明縮成灰色小字放在下面。
- 頁內用卡片分組，每組有標題。
- 改了設定後，角落短暫顯示「已儲存 ✓」。
- 規則清單照舊由 `schema.json` 自動產生；技能清單（優先、★ 專注、✕ 放逐、學到後放逐）、神祇清單、道具、職業選單要做到跟現在的功能完全相同。

## 架構

### 面板視窗

- `PanelForm` 保留為外框：F9 開關、按 X 只隱藏、置頂、記住視窗位置與大小，這些行為不變。
- 內容換成一個 WebView2。介面檔案（`index.html`、`panel.css`、`panel.js`）以 EmbeddedResource 打包進 exe（同內建範本的做法），由 `WebResourceRequested` 在虛擬網址（例如 `https://panel.rohelper/`）回應。發佈仍是單一 exe。
- WebView2 環境跟同一個 profile 的遊戲共用：遊戲用 `AppPaths.WebViewDir` 加上 `BrowserArgs` 建立 `CoreWebView2Environment`，同一個資料夾的第二個 WebView2 必須用同一個環境（選項不同會建立失敗），所以由 GameForm 把建好的環境交給面板。面板要等遊戲的環境建好才初始化，在那之前顯示「等待遊戲載入…」（同現在）。
- 介面不載入任何外部網址或 CDN：字型用系統的 Microsoft JhengHei UI，圖示用 emoji 或內嵌 SVG。

### C# 與介面之間的訊息

用 `PostWebMessageAsJson`（C# → 介面）與 `WebMessageReceived`（介面 → C#），每則訊息有 `type`：

| 方向 | type | 內容 |
|---|---|---|
| C# → 介面 | `schema` | 規則清單（同現在 OnSchema 收到的 EngineSchema） |
| C# → 介面 | `config` | 整份目前設定（ConfigStore.Changed 時送） |
| C# → 介面 | `status` | 狀態快照（見下） |
| C# → 介面 | `saved` | 設定已寫入，介面顯示「已儲存 ✓」 |
| 介面 → C# | `ready` | 介面載入完成，C# 補送 schema、config、status |
| 介面 → C# | `patch` | 改設定（物件），C# 呼叫 `IAutomation.SendPatch` |
| 介面 → C# | `topMost` | 置頂開關 |
| 介面 → C# | `command` | `export`、`import`、`applyOthers`、`resetStats`、`openFolder` 等動作 |

資料流向維持現在的單向循環：使用者操作 → `SendPatch` → 引擎改設定 → `ConfigStore.Changed` → 送 `config` 給介面 → 介面依設定重畫。介面不自己保存設定狀態。

匯入、匯出、套用到其他分身的對話框沿用現有 WinForms 對話框，由 `command` 觸發。

### 狀態快照（status）

新增一個純邏輯的組裝器（例如 `PanelSnapshot`），輸入引擎目前的狀態、`StatusHistory`、`RunStore` 的紀錄、`StallWatch`、目前時間，輸出總覽要的 JSON：

- `running`、`runs`、`runLimit`
- `step`：`{ mode: "expe" | "event", index, steps: [...] }`
- `action` 與 `history`（最近 3 筆）
- `alerts`：`[{ level: "error" | "warn", text }]`
- `run`（在野外）：地名、職業、遊戲時間、下一隻王、尋寶率、HP、選過的卡
- `lastRun`（不在野外）：時長、結果、尋寶率
- `today`：局數、每小時局數、存活率、開始時間、最近 10 局 `[{ secs, died }]`

送出規則：內容跟上次相同就不送；最多每 250 ms 送一次。

需要的新純邏輯，都要有單元測試：

- **步驟判斷**：由模式和目前動作（LobbyFlow／ExpeditionFlow 的動作、是否在野外、是否在結算）決定步驟條的位置。
- **今天累計**：由 `runs.jsonl` 的紀錄算出今天的局數、每小時局數、存活率、最近 10 局。「今天」以本機時間的日期為準。
- **警示清單**：由 StallWatch 的倒數、缺少的範本、職業、最近一次辨識是否失敗、OCR 是否可用組出來。

## 分階段

每個階段都要能單獨驗收，舊面板在第 3 階段之前一直保留可用。

1. **外框、訊息管道、所有設定頁**：新面板能完整取代舊面板的設定功能（所有規則、技能、神祇、道具、職業、紀錄、時間、備份）。總覽頁先只放現有的三行資訊。
2. **總覽儀表板**：狀態快照組裝器與三個純邏輯元件（含單元測試）、總覽頁四區。
3. **移除舊面板**：確認新面板所有功能都正常後，刪除 `PanelForm.Rules.cs`、`PanelForm.Lists.cs`、`PanelForm.Other.cs` 中被取代的 WinForms 程式，更新 README 與 HANDOFF。

## 測試與驗收

- C# 單元測試：步驟判斷、今天累計、警示清單、狀態快照的「沒變就不送」。
- 介面：每個階段實際啟動程式，用開發介面截圖面板，逐頁核對：
  - 每一種控制項（開關、數字、下拉、文字、技能清單的 ★ ✕）改了之後，設定檔真的改到、遊戲行為照新設定走、介面顯示「已儲存 ✓」。
  - 重開程式後設定與目前分頁都還在。
  - 多開（`--profile=B`）時兩個面板各自正確。
- 記憶體：記錄改版前後每個帳號的記憶體用量。

## 這次不做

- 遊戲視窗上方的選單列維持原樣。
- 「多開總覽」視窗、「視覺除錯」視窗維持原樣（之後可用同樣風格另做）。
- 亮色／暗色主題切換。

## 風險

- **記憶體**：每個帳號的面板多一個 WebView2 畫面，預估約多 100MB。跟遊戲共用環境可以降低一部分，第 1 階段完成時實測。
- **WebView2 環境共用**：環境選項必須跟遊戲完全相同，所以由遊戲視窗把環境交給面板，不在面板自己建立。
- **功能遺漏**：舊面板的細節（例如技能清單重建時延後處理、正在輸入的文字框不被覆蓋）要在新介面重新處理；第 1 階段以「逐項對照舊面板」驗收。
